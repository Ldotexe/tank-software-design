# Tank software design

Учебный проект на LibGDX. Управление: стрелки или WASD. Деревья блокируют движение танка.

## Запуск

Проект проверен с JDK 17. Если установлено несколько версий Java, выберите JDK 17 через `JAVA_HOME`.

```bash
bash gradlew run
bash gradlew test
bash gradlew build
```

Отчёт о тестах: `build/reports/tests/test/index.html`. Для unit-тестов не нужны окно и OpenGL.

## Структура

- `app` — запуск приложения и создание объектов игры.
- `game` — игровой цикл и интерфейсы ввода, обновления и отображения.
- `model` — танк, поле, препятствия и правила движения.
- `input` — обработка клавиатуры и привязки управления.
- `graphics` — слои отрисовки и изображения объектов.
- `graphics.util` — интерполяция и расчёты экранных координат.

## Hometask 3

`Tank` получает `MovementRules` и длительность перехода через конструктор. `GameField` реализует эти правила и проверяет коллекцию `Obstacle`, поэтому для нового препятствия не нужно менять поле или танк.

`GameSession` обновляет переданные объекты `Updatable`. `GameLoop` зависит от интерфейсов `InputHandler`, `Updatable` и `GameView`. Его можно использовать с другим вводом или без графического окна.

`GameRenderer` рисует список `RenderLayer`. `FieldRenderer` рисует карту, а `ObjectLayer<T>` — группу объектов через `ObjectRenderer<T>`. Для нового типа объекта достаточно реализовать его отрисовщик и подключить слой. Один отрисовщик с одной текстурой обслуживает всю группу объектов.

Длительность движения, пути к ресурсам и создание конкретных объектов находятся в `DefaultGameFactory`. Начальное расположение объектов передаётся через описание уровня. Чтобы добавить препятствие с изображением, нужно зарегистрировать его в поле и подключить соответствующую группу к отрисовке. Пути к текстурам и интерполяция передаются отрисовщикам через конструкторы.

`KeyboardHandler` позволяет добавлять действия на удержание (`bindHeld`) и однократное нажатие (`bindJustPressed`). `PlayerControls` принимает функцию движения, а не конкретный танк.

Сохранены управление, поворот перед препятствием и длительность движения (0.4 секунды). Выход за края карты остаётся разрешённым.

Тесты проверяют исходное поведение, замену правил движения, разные длительности перехода, препятствия из нескольких клеток, добавление обновляемых объектов, порядок игрового цикла и подключение новых слоёв отрисовки.

## Hometask 4

Добавлены два источника наполнения уровня: случайная генерация и чтение текстового файла. Они реализуют `LevelSource` и возвращают `LevelLayout` с размерами поля, деревьями и начальной позицией игрока. Сборка игры использует это описание для проверки препятствий и отрисовки.

Без аргументов создаётся случайное поле 10×8 с 20 деревьями. Можно выбрать режим и параметры:

```bash
bash gradlew run --args='--random'
bash gradlew run --args='--random 12 7 25'
bash gradlew run --args='--level src/main/resources/level.txt'
```

В текстовом файле `T` обозначает дерево, `X` — начальную позицию игрока, `_` — пустую клетку. Файл должен содержать непустое прямоугольное поле и ровно один `X`. Первая строка соответствует верхнему ряду. Пример из презентации находится в `src/main/resources/level.txt`.

Случайный генератор выбирает разные клетки для деревьев и игрока. Количество деревьев должно быть меньше количества клеток. Фон подстраивается под размеры уровня. Начальное окно имеет размер 960×640; весь уровень масштабируется под окно с сохранением пропорций, в том числе при изменении его размера. Проверка доступности клеток при движении остаётся прежней: выход за края поля разрешён.
